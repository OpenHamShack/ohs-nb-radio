# Strings and languages

OpenHamShack QO-100 NB and OpenHamShack Radio ship in English for the beta,
but no user-visible text belongs in code: it goes through Qt's translation
mechanism, with English as the source language, so another language is a
catalog away. The family-wide rule is `~/openhamshack/docs/contract/I18N.md`;
this page is how it works here.

## Three catalogs, two apps

| Catalog | Holds | Loaded by |
| --- | --- | --- |
| `ohscore/i18n/ohscore_en.ts` | the shared window and widgets (`BaseWindow`'s menus, the About box, the logbook...) | both apps |
| `ohsnb/i18n/ohsnb_en.ts` | QO-100 NB's own window, badges, transmit card, skimmer | QO-100 NB |
| `ohsradio/i18n/ohsradio_en.ts` | Radio's own window, band bar, chips, diagnostics | Radio |

A string goes in the catalog of the package whose code says it:
`tools/i18n.py extract` reads `ohscore/` for the first, `ohsnb/` and `ohsradio/`
for the others. Each `.ts` has its compiled `.qm` beside it, committed.

The loader is `ohscore/i18n/__init__.py`. Each app's `make_app()`
(`ohsnb/ui/__init__.py`, `ohsradio/ui/__init__.py`) calls `i18n.install()` with
the shared catalog and its own, right after the QApplication exists and
before any window is built: `tr()` is answered when a widget is made, so a
catalog installed later changes nothing on screen. It runs on every
`make_app()` call, not just the first, because the test suite builds both
apps' windows in one process and each needs its own catalog in front.

## Adding a string

Write the English inside `self.tr()` in any `QObject` subclass (every widget
and window), or `QCoreApplication.translate("Context", "...")` elsewhere:

```python
self.setWindowTitle(self.tr("OpenHamShack Radio"))
a = QAction(self.tr("Check radio…"), self)
self.count.setText(self.tr("%n QSO(s)", "", len(rows)))
txt = QCoreApplication.translate("SkimView", "%n signal(s)", "", n)   # in a plain function
```

- **Whole sentences, named placeholders.** `{app}` filled by `.format()`
  after `tr()`, never `"About " + name`: other languages put the name
  elsewhere.
- **Plurals through `%n`**, never `'s' if n != 1`. Write the English as
  `signal(s)`: `tools/i18n.py extract` writes the two English forms
  ("signal", "signals") into the catalog from that. A plural the convention
  cannot spell ("entry/entries") has its forms written into the `.ts` by
  hand once, and the check says which.
- **Not translated:** callsigns, locators, mode names, file names, key
  sequences (`QKeySequence("Ctrl+Q")` stays as written; Qt shows it in the
  user's language).
- **Frequencies** through `ohscore.i18n.fmt.frequency(hz, unit, decimals)`:
  kHz below 30 MHz and MHz above unless the field fixes the unit, the
  locale's decimal separator, never grouped, a no-break space before the
  unit. It is used today by NB's IC-9700 line on the transmit card and
  Radio's FT8/FT4 key tooltips on the band bar. The big frequency readouts
  are not converted, on purpose: they are digit-by-digit dials whose
  grouped digits ("1 296.200 000") are each a wheel target, which the
  shared rules do not cover.
- **The subclass trap.** PyQt's `self.tr()` looks strings up under the
  class of the object, not the class whose code called it. ohscore is full
  of base classes whose subclasses are what get built (`BaseWindow` is
  only ever an app's `MainWindow`; `About` is each app's `About`), so a
  string in such a class is written
  `QCoreApplication.translate("BaseWindow", "...")`, spelt out in full:
  pylupdate6 and the check recognise no shorter alias.

Then refresh the catalogs (below) and commit the `.ts` and `.qm` with the
code.

## Sentences no widget says: gettext

The engines' toasts and refusals, and `ValueError` messages a window shows
as they are, are not Qt strings: the engine runs without Qt (`--headless`,
`--server`, a store container), and must import without PyQt. They go
through gettext, one domain per package (`ohscore/i18n/text.py`):

```python
from ohscore.i18n.text import _      # in ohscore
from ohsnb.i18n import _             # in ohsnb (ohsradio.i18n in ohsradio)

raise ValueError(_("{title}: type must be down or up").format(title=title))
self.toast(ngettext("Saved {n} memory", "Saved {n} memories", n).format(n=n))
```

The same rules as Qt's: whole sentences, `{name}` placeholders filled by
`.format()` after `_()`, never an f-string inside it (the template would
hold the f-string's source, which nothing looks up), plurals through
`ngettext`, `pgettext` where one English word means two things.

The English templates, `<package>/i18n/<package>.pot`, are written by
`tools/i18n.py pot` and committed; `tests/test_i18n.py` runs
`tools/i18n.py pot --check`, and shack-i18n-check checks each call's msgid
against them. Translations will go under `<package>/i18n/locale/<lang>/
LC_MESSAGES/<package>.mo`; English, the source, needs none.

## Regenerating the catalogs

```
tools/i18n.py extract       # pylupdate6 refreshes the three .ts files, then compiles the .qm files
tools/i18n.py extract ohsnb  # only ohsnb's .ts (ohscore, ohsnb, ohsradio)
tools/i18n.py compile       # .ts -> .qm only, after editing a .ts by hand
tools/i18n.py pot           # the gettext templates, from the _()/ngettext()/pgettext() calls
```

`extract` needs `pylupdate6`, which comes with pip's PyQt6 but not with
Debian's. Once per machine:

```
python3 -m venv --system-site-packages ~/build/venvs/ohs-qt
~/build/venvs/ohs-qt/bin/pip install PyQt6
PYLUPDATE6=~/build/venvs/ohs-qt/bin/pylupdate6 tools/i18n.py extract
```

The `.qm` files are compiled by `tools/i18n.py` itself (byte for byte what
Qt's `lrelease` writes), and committed. The `.deb` copies each package as it
is, so the catalogs ship without a build step; the Windows and macOS
PyInstaller specs list `ohscore/i18n` and the app's own `i18n` folder as data
(tests/test_windows_bundle.py and test_macos_bundle.py check it). The
English catalogs are loaded even in English, because they carry the English
plural forms.

**Which language:** `SHACK_LOCALE` (for example `de`, `pt_BR`, `en-XA`) if
set, otherwise the desktop's preferred languages; a language is taken if
any of the app's catalogs has it, and one without a catalog falls through to
English. `tools/i18n.py pseudo` writes the en-XA pseudo-locale (accented,
40% longer, bracketed) beside each of the three English catalogs, where the
loader looks:

```
tools/i18n.py pseudo
SHACK_LOCALE=en-XA python3 -m ohsradio
```

That shows at a glance any string that escaped `tr()` and any label that
clips. The files are ignored by git; do not commit them.

## The check and the baseline

`tools/i18n.py check` runs ohs-libs' `shack-i18n-check` (vendored as a pinned
wheel in `tools/vendor/`), and `tests/test_i18n.py` runs it in every suite run,
so it fails the tests. It finds user-visible literals passed to Qt's text
APIs and to these apps' own widgets (the sink list in `.i18n-check.toml`),
and a `ValueError` raised with a literal message (ohscore and the apps raise
them with sentences the windows show as they are), and checks that every
string the code asks for is in an English catalog.

- **`i18n-pending.txt` is the baseline**: the literals that were already in
  the code when the check arrived. They pass for now; anything new fails. The
  last line of the check's output (also printed in the test run) gives the
  count, and M3 drives it to zero. Converting a literal leaves its baseline
  line matching nothing, which fails until `tools/i18n.py baseline` removes
  it, so the count only falls. `baseline` never adds lines; `--add-new` was
  for writing it the first time.
- **`i18n-allow.txt` is for literals that are not language**, each with a
  reason. It was empty when the check arrived. An entry that stops matching
  fails the check.
- **Data tables are not sinks**: the settings registry's descriptions
  (`state.py`), the licence tables and the band plans are M3's, extracted
  into a gettext domain in the engines rather than written as Qt strings.
- A new widget that shows a text argument goes into the sink list, so the
  check sees it.
